## Fallback Chain

The system uses a 3-tier fallback chain to ensure copy is always available:

1. **Requested Locale** → Try user's requested locale (e.g., 'es')
2. **English Fallback** → Fall back to English if locale unavailable
3. **Generic Fallback** → Use generic copy from `fallbackContent.ts`

**Example:**
- User locale: `es-MX` → Normalized to `es`
- Loop: `tutor_card`, Persona: `tutor`
- Try: `COPY_TEMPLATES.tutor_card.tutor.es` ✅ Returns Spanish copy
- If missing → Try `COPY_TEMPLATES.tutor_card.tutor.en` (English)
- If missing → Try `FALLBACK_COPY.tutor_card.tutor` (generic)

## How It Works

### Backend Flow

```typescript
// 1. Orchestrator extracts user locale
const userLocale = userData.locale || 'en';

// 2. Includes locale in decision response
return {
  shouldShow: true,
  loopType: 'tutor_card',
  persona: 'tutor',
  locale: 'es',  // NEW
  copyKey: 'tutor_card.tutor',
  // ... rest
};
```

### Frontend Flow

```typescript
// 1. Hook fetches copy based on user's profile
const copy = useLocalizedCopy('tutor_card');

// 2. Internally resolves to:
// - loopType: 'tutor_card'
// - persona: user.role (e.g., 'tutor')
// - locale: user.locale (e.g., 'es')

// 3. Returns localized copy
// → "¡Comparte tu calificación de 5⭐ con estudiantes potenciales!"
```
