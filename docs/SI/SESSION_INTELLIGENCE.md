# Session Intelligence: Complete Documentation

## Overview

Session Intelligence (SI) is a comprehensive system for capturing, transcribing, analyzing, and presenting tutoring session data. It provides parents with insights into their child's learning through weekly progress reels and detailed session transcripts.

---

## Architecture

### Data Flow

```
1. Parent/Tutor uploads video/audio recording
   ↓
2. Storage trigger → transcribeRecording (Whisper API)
   ↓
3. Firestore trigger → dailySummarizer (GPT-4o-mini)
   ↓
4. Daily summaries accumulate throughout week
   ↓
5. Sunday 6 PM → weeklyAggregator
   ↓
6. Weekly summary → generateWeeklyReel
   ↓
7. Push notification → Parent views reel
   ↓
8. Daily cleanup job removes old recordings (30 days)
```

## Event Schema (SI-10)

### Event Types

**Upload Events:**
- `recording_upload_started` - User begins uploading recording
- `recording_upload_succeeded` - Upload completes successfully
- `recording_upload_failed` - Upload fails

**Transcription Events:**
- `transcription_started` - Whisper API call begins
- `transcription_succeeded` - Transcript generated successfully
- `transcription_failed` - Transcription fails

**Summary Events:**
- `daily_summary_created` - Daily summary generated
- `weekly_summary_created` - Weekly aggregation complete
- `weekly_reel_generated` - Reel created from weekly summary

**User Events:**
- `weekly_reel_viewed` - User opens weekly reel
- `transcript_viewed` - User views transcript
- `recording_viewed` - User plays recording

### Timing Metrics

- `uploadMs` - Time to upload file to Storage (client-side)
- `processMs` - Time to process/watermark (if implemented)
- `transcribeMs` - Time for Whisper API to transcribe
- `summarizeMs` - Time for GPT-4o-mini to summarize

**Performance Targets:**
- Upload: < 10 seconds (for 50MB file)
- Transcription: < 90 seconds (for 30-minute recording)
- Daily summary: < 5 seconds
- Weekly summary: < 30 seconds

### Error Categories

- `upload_error` - Network, storage, or file format issues
- `transcription_error` - Whisper API failures
- `llm_error` - GPT-4o-mini failures
- `storage_error` - Firebase Storage issues
- `permission_error` - Firestore security rule violations
- `quota_error` - API rate limits or quotas exceeded
- `network_error` - Network connectivity issues
- `unknown_error` - Uncategorized errors

## Retention Policy (SI-11)

### What We Keep

**Indefinitely:**
- Transcripts (`/transcripts/**`)
- Daily summaries (`/summaries/**/daily/**`)
- Weekly summaries (`/summaries/**/weekly/**`)
- Progress reels (`/reels/**` - expire after 30 days via `expiresAt`)

**30 Days:**
- Raw recordings (`/recordings/**` + Storage files)
- After 30 days, recordings are automatically deleted by `scheduledRecordingCleanup`

### Why This Policy

**Cost Management:**
- Storage costs for raw video/audio files can grow quickly
- Transcripts are much smaller (text) and provide the same value
- 30 days allows time for parents to download if needed

**Privacy:**
- Limits exposure of raw audio/video content
- Transcripts already have PII redaction applied
- Reels expire automatically to prevent indefinite data retention

**Analytics:**
- Summaries and transcripts provide all historical analytics value
- No need to keep raw files for insights

### Cleanup Schedule

**Scheduled Function:** `scheduledRecordingCleanup`
- **Frequency:** Daily at 2 AM UTC
- **Retention:** 30 days
- **Target:** Raw recordings in Storage + Firestore
- **Preservation:** Transcripts, summaries, reels remain

**Manual Cleanup:** `manualRecordingCleanup`
- Callable Cloud Function (admin only)
- Custom retention period
- Useful for testing or emergency cleanup

## Privacy & Consent

### Required Consent

**Before reel generation:**
- User must have `consents.progressSharing = true`
- Checked in `generateWeeklyReel()` and `generateProgressReel()`
- No reel created if consent not granted

**PII Redaction:**
- All reels have PII redacted via `redactForProgressReel()`
- Removes: names, emails, phone numbers, school names
- Applied to: highlights, aggregatedSummary fields

### Firestore Security Rules

**Read Access:**
- Only conversation participants can read recordings, transcripts, summaries
- Enforced via: `request.auth.uid in get(...).data.participants`

**Write Access:**
- Only Cloud Functions can write (using Admin SDK)
- All client writes denied via `allow write: if false`

**Privacy Toggle (Future):**
- Per-conversation `transcriptionEnabled` flag
- Would disable transcription for sensitive conversations
- Not yet implemented (SI-11 task)

## Cost Estimates

### Per Recording

**Upload (50MB video, 30 minutes):**
- Storage: ~$0.001/month
- Transcription (Whisper): ~$0.18 (30 min × $0.006/min)
- Daily Summary (GPT-4o-mini): ~$0.001 (500 tokens)
- **Total per recording:** ~$0.18

**Per Week (5 recordings):**
- Transcription: $0.90
- Daily summaries: $0.005
- Weekly summary: $0.001
- Weekly reel generation: $0.001
- **Total per week per conversation:** ~$0.91

**Storage (after cleanup):**
- Raw recordings: Deleted after 30 days
- Transcripts: ~10KB each = negligible
- Summaries: ~2KB each = negligible

**Monthly Estimate (100 active conversations):**
- 100 conversations × 4 weeks × $0.91 = **$364/month**
- Storage: ~$5/month (raw files deleted after 30 days)
- **Total: ~$369/month**

**Cost Optimization:**
- Cleanup after 30 days saves ~$50/month in storage
- Reusing carousel UI (no video encoding) saves ~$100/month
- Batch processing reduces Cloud Function costs

## Troubleshooting

### Transcription Not Working

**Check:**
1. `OPENAI_API_KEY` environment variable set
2. Storage trigger deployed (`transcribeRecording`)
3. Recording path correct: `/recordings/{cid}/{rid}.{ext}`
4. Supported format: `.m4a`, `.mp3`, `.wav`, `.mp4`, `.webm`

**Logs:**
```bash
firebase functions:log --only transcribeRecording
```

### Weekly Summaries Not Generating

**Check:**
1. Scheduled function deployed (`aggregateWeeklySummaries`)
2. Cron schedule: Sunday 6 PM America/Chicago
3. Daily summaries exist for the week
4. Query `/si_analytics` for `weekly_summary_created` events

**Manual Trigger:**
```bash
# In Firebase console or using Admin SDK
aggregateWeeklySummaries()
```

### Cleanup Not Running

**Check:**
1. Scheduled function deployed (`scheduledRecordingCleanup`)
2. Cron schedule: Daily 2 AM UTC
3. Recordings have `uploadedAt` timestamp
4. Query `/si_analytics` for `cleanup_completed` events

**Manual Trigger:**
```bash
manualRecordingCleanup({ retentionDays: 30 })
```

### High Costs

**Check:**
1. Cleanup running daily (delete old recordings)
2. Transcription only on valid formats
3. No duplicate transcriptions (idempotency checks)
4. Monitor `/si_analytics` for volume

**Optimization:**
- Reduce Whisper API calls (check for existing transcripts)
- Compress videos before upload (client-side)
- Batch summarization (multiple recordings per LLM call)
